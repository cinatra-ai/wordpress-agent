## Directory Purposes

**`cinatra/`:**
- Purpose: Cinatra platform artefacts — the machine-readable agent definition
- Contains: `oas.json` (agentspec 26.1.0 WayFlow Flow spec)
- Key files: `cinatra/oas.json`

**`skills/wordpress-agent/`:**
- Purpose: Agent skill definitions — LLM behavioural rules and editing procedures
- Contains: `SKILL.md` (step-by-step editing protocol, allowed/forbidden primitives, output schema)
- Key files: `skills/wordpress-agent/SKILL.md`

**`.github/workflows/`:**
- Purpose: CI/CD pipeline for this extracted extension repo
- Contains: `ci.yml` (build + kind-gates), `release.yml` (reusable extension release)
- Key files: `.github/workflows/ci.yml`, `.github/workflows/release.yml`

**`.planning/codebase/`:**
- Purpose: GSD codebase map documents generated by `/gsd-map-codebase`
- Generated: Yes (by GSD tooling)
- Committed: Yes (`.planning/` is permitted per project policy)

## Key File Locations

**Agent Definition:**
- `cinatra/oas.json`: Complete WayFlow flow spec — all nodes, edges, I/O contracts, LLM prompt templates

**Skill / Prompt Rules:**
- `skills/wordpress-agent/SKILL.md`: Injected as LLM system context; defines the demote-then-edit procedure and forbidden primitives

**CI Gate:**
- `extension-kind-gate.mjs`: Self-contained Node.js script; run as `node extension-kind-gate.mjs --package-root .`; audits `cinatra/oas.json` for retired primitives in prompt strings

**Package Identity:**
- `package.json`: Declares `name: "@cinatra-ai/wordpress-agent"`, `cinatra.kind: "agent"`, `cinatra.apiVersion: "cinatra.ai/v1"`

**TypeScript Config:**
- `tsconfig.json`: Targets `src/` → `dist/` (ES2023/ESNext/bundler). No `src/` exists in this repo — compilation is owned by the Cinatra monorepo.

**Developer Reference:**
- `AGENTS.md`: A2A input/output contracts, MCP primitives used, timeout values, local dev instructions, critical notes on demote-then-edit asymmetry vs Drupal agent

## Naming Conventions

**Files:**
- Skill files: `SKILL.md` (uppercase) under `skills/<agent-name>/`
- Flow spec: `oas.json` (lowercase) under `cinatra/`
- CI scripts: `kebab-case.mjs` at repo root (e.g. `extension-kind-gate.mjs`)
- Workflow files: `kebab-case.yml` under `.github/workflows/`

**Directories:**
- Skill directories match the package/agent name: `skills/wordpress-agent/`
- Platform artefacts live in `cinatra/` (flat, not namespaced)

## Where to Add New Code

**New MCP primitive support:**
- Document the primitive in `AGENTS.md` (MCP primitives table)
- Add behavioural rules to `skills/wordpress-agent/SKILL.md`
- Update the `edit` ApiNode prompt template in `cinatra/oas.json` if the system/user text needs updating
- If the primitive name appears in `extension-kind-gate.mjs`'s banned list, verify it is not erroneously flagged

**New flow node or output field:**
- Add node definition under `$referenced_components` in `cinatra/oas.json`
- Add control-flow edge in `control_flow_connections`
- Add data-flow edges in `data_flow_connections`
- Update top-level `inputs`/`outputs` arrays if the flow contract changes

**TypeScript source (future):**
- Create `src/` at repo root per `tsconfig.json` conventions
- Entry point would follow `src/index.ts` pattern (conventional for Cinatra extensions)
- Tests would go in `src/**/*.test.ts` (no test framework currently configured)

**New skill rules:**
- Edit `skills/wordpress-agent/SKILL.md` directly — it is injected verbatim as system context

## Special Directories

**`cinatra/`:**
- Purpose: Machine-readable platform artefacts consumed by Cinatra marketplace and WayFlow runtime
- Generated: No (hand-authored / extraction-script seeded)
- Committed: Yes

**`.planning/`:**
- Purpose: GSD planning and codebase map documents
- Generated: Yes (by GSD tooling)
- Committed: Yes (explicitly permitted by project policy)
